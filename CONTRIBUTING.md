# Contributing to Quran Discipline

Thanks for your interest in making Quran Discipline better. This project
helps people protect their attention and worship — every contribution counts.

## Getting started

1. Fork the repository and clone your fork.
2. Use Node.js 22+ and npm.
3. Install and verify the baseline:

   ```bash
   npm install
   npm run lint
   npm run typecheck
   npm test
   npm run build
   ```

4. Create a branch for your change:

   ```bash
   git checkout -b feature/my-change
   ```

## Development workflow

- `npm run dev` — watch build. Load/refresh the unpacked extension from
  `.output/chrome-mv3` in `chrome://extensions` after changes.
- `npm run test` / `npm run test:watch` — unit tests (Vitest). Pure logic
  lives in `src/helpers` and `src/storage`; please add tests for behavior
  changes there.
- `npm run lint` and `npm run format` — ESLint + Prettier. CI runs both.
- `npm run typecheck` — TypeScript must pass with no errors.

### Architecture notes

- **Dashboard ↔ extension bridge**: the companion dashboard talks to this
  extension over `chrome.runtime.onMessageExternal`, gated by
  `externally_connectable`. The full contract — every message type, the
  response envelope, the block-page redirect URL, storage keys, and gotchas —
  is documented in [docs/dashboard-bridge.md](docs/dashboard-bridge.md). Read
  it before changing `src/entrypoints/background/`, `src/types/`, or
  `wxt.config.ts`.
- **Blocking logic** is a pure function (`src/helpers/blocking.ts`) shared by
  the background worker and tests. Prefer extending it over adding inline
  conditionals in `src/entrypoints/background/index.ts`.
- **Storage** access goes through `src/storage/*`. Never call
  `chrome.storage` directly from UI code.
- The **manifest** is generated by WXT (`wxt.config.ts`). Keep permissions
  minimal and document any new one in the README table.

## Pull requests

- Keep PRs focused — one concern per PR.
- Fill in the PR template; link related issues.
- Ensure CI is green (lint, typecheck, tests, build).
- Describe user-visible changes clearly; note anything that affects privacy
  or permissions explicitly.
- By contributing, you agree your contribution is licensed under the
  project's [GPL-3.0](LICENSE) license.

## Proposing features

Open an issue first for large changes (new permissions, storage schema
changes, UX redesigns) so direction can be discussed before code is written.
Small fixes and tests are welcome as direct PRs.

## Reporting bugs

Use the bug report issue template. For security issues, **do not** open a
public issue — see [SECURITY.md](SECURITY.md).

## Code of conduct

This project follows the [Contributor Covenant 2.1](CODE_OF_CONDUCT.md).
Be respectful, especially around the religious context of this tool.
